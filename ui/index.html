새 계획

협업 계획 세우기

여러 팀의 목표를 하나의 실행 가능한 계획으로 정리합니다.

01목표

승인할 결과를 목표로 정의하세요

관련 작업은 하나의 계획으로 묶고, 팀별로 달성할 결과를 각각의 목표로 정의합니다.

목표 목록

각 작업 단위는 아래 목표 중 하나에 연결됩니다.

계속하려면 목표를 하나 이상 작성해야 합니다.
02범위

계획의 경계와 완료 조건을 정하세요

포함 범위는 목표와 작업 단위가 설명합니다. 여기서는 제외 범위와 검증 가능한 완료 기준을 분명히 합니다.

영향을 받는 서비스 *필수

등록된 서비스를 불러오는 중입니다.

제외 범위*필수 결정

의도적으로 하지 않는 일을 적으면 계획이 회의 중에 넓어지는 것을 막을 수 있습니다.

03작업

목표를 독립적으로 실행할 작업으로 나누세요

ID와 브랜치는 자동 생성됩니다. 여러 담당자가 필요하면 충돌 없는 작업 단위로 나누세요.

아직 작업이 없습니다목표를 구현할 첫 작업 단위를 추가해 주세요.
04계약

서비스가 함께 지킬 계약을 연결하세요

계약 파일마다 참여 서비스를 선택해 어느 저장소 사이의 약속인지 명확히 합니다.

계약 문서

직접 작성하거나 Markdown 또는 JSON 파일을 업로드할 수 있습니다.

05검토

저장 전에 실행 가능한 계획인지 확인하세요

초안 · 아직 저장되지 않음
자동 검사는 초안의 완성도를 확인할 뿐, 사람의 승인을 대신하지 않습니다.

01

필수 입력목표·완료 기준·작업 책임

02

충돌 검사경로·의존성·계약 매핑

03

생성 검증저장소 규칙과 파일 미리보기

아직 검토하지 않았습니다검토를 실행하면 수정할 항목과 생성될 파일을 보여 드립니다.

계획 검토를 통과하면 초안 저장 버튼이 활성화됩니다. 저장 후에도 사람의 승인과 병합이 필요합니다.

검토를 실행하면 선택한 파일의 역할과 변경 내용이 여기에 표시됩니다.


            
초안 저장 이후아래에서 승인 요청으로 확정하고 계획 PR을 올립니다. 리뷰와 병합은 GitHub에서 사람이 합니다.

          

          

            
승인 요청과 계획 PR
저장한 계획을 승인 상태로 확정하고 계획 PR을 올립니다.


            

              
1. 승인 요청으로 확정
대기

              
작업 상태를 approved와 ready로 바꿔 계획 PR에 담습니다. 이 값이 병합된 커밋에 들어 있어야 작업 지시서를 발급할 수 있습니다. 확정하면 UI에서 더 이상 이 계획을 편집하지 않습니다.

              

              

            


            

              
2. 계획 PR 올리기
대기

              
계획 브랜치를 만들어 changes/ 아래 파일만 커밋하고 push한 뒤 PR을 엽니다. 병합은 하지 않습니다.

              

              

            


            

              
3. 병합 확인
대기

              
작성자 본인이 CI와 내용을 확인해 GitHub에서 병합하면, 여기서 머지 커밋 SHA를 가져와 작업 지시서 단계로 넘어갑니다.

              

              

            

          

        

      

    

  


  
    

      
저장소 연결
서비스 등록

      
GitHub URL을 입력하면 저장소 이름으로 ID를 만들고 기술 스택을 확인합니다. 먼저 등록 전 확인을 통과해야 등록할 수 있습니다.

      
      

      
GitHub URL을 입력하면 등록 전 확인을 실행할 수 있습니다.

      
      
    

  

  
    

      
계획 승인 후
작업 지시서 만들기

      
병합된 계획을 고르면 실행 가능한 작업을 확인하고 담당자별 지시서를 만듭니다. 담당자가 지시서로 작업하는 방법은 저장소 루트의 WRITER.md에 있습니다.
